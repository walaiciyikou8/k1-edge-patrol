# K1 板端运行清单（串口 / 无桌面也能跑）

> 场景：4.3" 屏暂时不显示（桌面问题），但**代码、摄像头、桥接、算法全部可以先跑通**。
> 演示时也可以用 HDMI 显示器，程序完全一样。

## 最快上手（解压后两条命令）

```bash
cd k1-edge
python3 tools/selftest.py     # 期望 RESULT PASS=35 FAIL=0（不需要摄像头/屏）
sh run-k1.sh --real           # 自动选显示方式 + 自动选摄像头，直接跑
```

`run-k1.sh` 会自动判断：有桌面就开窗口、没桌面就直写 framebuffer、都没有就用网页屏；
摄像头写 `auto`，板上自动取 `/dev/video0`，电脑上自动取 0 号。

---

## 0. 拷代码到板子

把 `k1-edge-board.zip` 拷到 U 盘 → 插到板子 → 串口里：

```bash
mkdir -p /root/k1
mount /dev/sda1 /mnt          # U 盘一般就是 sda1；没有就 lsblk 看一下
cp /mnt/k1-edge-board.zip /root/k1/
cd /root/k1 && unzip -o k1-edge-board.zip
cd k1-edge
```

（用 scp 也行：`scp k1-edge-board.zip root@板子IP:/root/k1/`）

> U 盘拷过来会丢可执行位，用 `sh run-k1.sh …` 调用最省事，或者先 `chmod +x run-k1.sh`。

## 1. 环境检查（一次就够）

先装系统依赖（摄像头 + NPU runtime，按官方实验套件）：

```bash
sudo apt-get update
sudo apt-get install -y python3-numpy python3-opencv python3-pil \
  python3-spacemit-ort spacemit-onnxruntime spacemit-tcm opencv-spacemit
```

给 NPU 用的 `/dev/tcm` 开权限（否则推理会报 `tcm buffer acquire failed`）：

```bash
echo 'KERNEL=="tcm", GROUP="plugdev", MODE="0660"' | sudo tee /etc/udev/rules.d/99-spacemit-tcm.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
sudo usermod -aG plugdev bianbu     # 重新登录生效
```

然后一键体检（会查 依赖 / NPU / 摄像头 / 模型 / 底库 / 字体）：

```bash
python3 tools/check_env.py
```

- 报 `ModuleNotFoundError` → 上面 apt 那条没装全
- 中文显示成方块 → `sudo apt install -y fonts-noto-cjk`
- 摄像头那一项 FAIL → 见第 2 节配摄像头

## 2. 摄像头（IMX219 · MIPI → /dev/video50）

K1 的 MIPI 相机是**虚拟相机**，先识别生成配置，才会有 `/dev/video50`：

```bash
# 断电接好 IMX219 后上电，先识别摄像头（15pin/2-lane 用 csi3；22pin/4-lane 用 csi1）
cam-test /usr/share/camera_json/csi3_camera_detect.json
ls -l /dev/video50                    # 有这一行才算成功
```

取流必须走 SpacemiT 的 `spacemitsrc`（NV12 非连续平面，普通 v4l2src 会报 `non-contiguous planes`）。**本项目已内置**：`--camera /dev/video50 --camera-backend gstreamer` 会自动用 `spacemitsrc` 读 `csi3_camera_auto.json`（自动在 `/usr/share/camera_json/`、`/tmp/` 里找）。

```bash
python3 main.py --list-cameras       # 看有哪些 /dev/video* 和相机配置 json
```

## 3. 自检（不需要摄像头、不需要屏）

```bash
python3 tools/selftest.py
```

看到 `RESULT PASS=36 FAIL=0` 就是整条链路通了（人脸库扫描 → 命中建事件 → 抓拍落盘 → 队列 → 桥接 API → LCD 处置回写）。

## 4. 亮屏诊断（关键一步，判断屏到底能不能显示）

```bash
python3 tools/fb_test.py
```

规则：**盯着 4.3" 屏**，逐块 fb 会闪 红 → 绿 → 蓝 → 白底文字。

| 现象 | 结论 | 下一步 |
|---|---|---|
| 某一块出现红/绿/蓝 | 屏是好的，只是没人在它上面画 | 记下那块 `/dev/fbN`，用第 4 步 |
| 全部都没反应 | 这块屏没有 fb 画布（只有 DRM/KMS） | 先按第 5 步跑网页屏，演示用 HDMI |

也可以只看一下有哪些 fb：

```bash
python3 main.py --list-fb
```

## 5. 直接把巡更界面画到小屏（不需要 X / 桌面）

python3 main.py --mock --serve-only --ui-mode fb --fb /dev/fb1

## 6. 网页屏（最稳，任何环境都能用）

```bash
python3 main.py --mock --serve-only --ui-mode web --no-browser
```

然后**任何一台同一局域网的设备**（手机/笔记本/HDMI 屏上的浏览器）打开：

```
http://板子IP:8088/screen
```

能看能点，和触摸屏体验一致。演示时这是最不会掉链子的方案。

## 7. 接摄像头跑真实流程

先下模型（一次就够，模型会跟包一起放进 `models/`）：

```bash
python3 tools/get_models.py --check     # 看模型在不在
python3 tools/real_check.py             # 离线验证：检测 + 比对，不接摄像头
```

然后：

```bash
python3 main.py --real --camera /dev/video50 --camera-backend gstreamer --ui-mode web --no-browser
```

- `--real` = YuNet 检测 + SFace 识别（真识别，不是 mock）；
- `--camera /dev/video50 --camera-backend gstreamer` = 走 `spacemitsrc` 读 MIPI 虚拟相机（IMX219 必须这样，普通 v4l2 会报 non-contiguous planes）；
- 没网没模型时 `--real` 会自动降级 mock，不会中断演示；
- 想先用 mock 快速验证流程：`python3 main.py --mock --replay ./demo_frames`。

后台地址默认 `http://127.0.0.1:8088`，接口清单见 `README.md`。

## 8. 演示彩排：照片回放（不需要真人站在镜头前）

演示前想反复练流程、又不想每次都找人"演嫌疑人"，用照片回放代替摄像头：

```bash
mkdir -p demo_frames
cp gallery/suspect/张三/*.jpg demo_frames/
cp gallery/staff/李四/*.jpg  demo_frames/
```

```bash
python3 main.py --real --replay ./demo_frames --replay-hold 4 --ui-mode web --no-browser
```

- 每张照片停留 `--replay-hold` 秒，然后自动切下一张，**完全走真实的检测→识别→告警→落盘→上报流程**；
- 照片会等比填充到 1280×720（不会把脸拉变形）；
- 想打乱顺序加 `--replay-shuffle`（配置文件里 `replay_shuffle=true`）。

现场演示时把 `--replay` 换成 `--camera /dev/video0` 即可，其余参数一字不改。

## 9. 演示方案对照（按现场有什么屏来选）

| 现场条件 | 怎么显示 | 命令 |
|---|---|---|
| 4.3" 屏正常 + 有桌面 | OpenCV 窗口 | `python3 main.py --real --camera /dev/video0 --ui-mode window --no-fullscreen` |
| 4.3" 屏正常 + 没桌面 | 直写 fb | `python3 main.py --real --ui-mode fb --fb /dev/fb1` |
| **借来的 HDMI 显示器**（无需桌面） | 直写 HDMI 的 fb | `python3 main.py --real --ui-mode fb --fb /dev/fb0` |
| 只有手机/笔记本 | 网页屏 | `python3 main.py --real --ui-mode web --no-browser` + 手机开 `http://板子IP:8088/screen` |

> 屏是借的、不确定是哪一块时，先跑 `python3 tools/fb_test.py`：哪块 fb 在那个屏上出红绿蓝，就用那块。
> 没有鼠标/触摸时，点击操作可以让手机打开网页屏来点（同一套接口，事件会同步到端侧）。

## 11. 没有显示器：TigerVNC 虚拟屏（不用重新烧录）

显示器坏了 / 借不到屏，也能完整开发和演示。**板子不需要重刷镜像**，只装一个软件包。

### 10.1 先联网并拿到 IP（串口里）

```bash
nmcli device wifi list                     # 列出可用 WiFi
nmcli device wifi connect "你的WiFi名" password "你的密码"
hostname -I                                # 记下第一个 IP，例如 192.168.1.23
```
（插网线的话直接 `hostname -I` 就行，不用配 WiFi。）

### 10.2 装 TigerVNC 服务端（就这一步"下载"）

```bash
apt update
apt install -y tigervnc-standalone-server tigervnc-common
```

> 说明：`tigervnc-standalone-server` 自带 `Xvnc`——它同时是 X 服务器和 VNC 服务端，
> **不需要物理显示输出、也不需要桌面环境**，所以屏坏了完全不影响。

### 10.3 一条命令起虚拟屏 + 跑巡更程序

```bash
cd /root/k1/k1-edge
sh run-k1-vnc.sh                 # 默认 800×480、端口 5901、密码 k1patrol
```

脚本会：写 `~/.vnc/xstartup`（内容 = **只跑巡更程序**）→ 开一个 800×480 虚拟屏 `:1`（端口 5901）→ 打印连接地址。

> ⚠️ 关键点：TigerVNC 每次开会话都会执行 `~/.vnc/xstartup`。默认那个脚本会拉起**整个 LXQt 桌面**，
> 于是 VNC 里看到的是桌面（这台板子的桌面本身有问题，会出现一半壁纸一半黑），**看不到我们的界面**。
> 本脚本已把 xstartup 改成"只 exec `main.py --ui-mode window`"，所以 VNC 里就是巡更界面本身。
> 想临时看完整桌面就加 `--desktop`。

### 10.4 电脑端看画面

装个 VNC 客户端（TigerVNC Viewer / RealVNC Viewer 都行），连：

```
板子IP:5901        密码：k1patrol
```

看到的画面就是 4.3" 屏上原本要显示的巡更界面，触摸点击用鼠标代替。

手动等价命令（不想用脚本时，单行版本便于串口粘贴；先 cd 到项目目录）：

```bash
vncserver -kill :1 2>/dev/null

printf '#!/bin/sh\nunset SESSION_MANAGER\nunset DBUS_SESSION_BUS_ADDRESS\ncd %s\nexec python3 main.py --real --ui-mode window\n' "$PWD" > ~/.vnc/xstartup
chmod +x ~/.vnc/xstartup

vncserver :1 -geometry 800x480 -depth 24 -rfbport 5901 -localhost no
```

排查：连上还是黑屏/空屏时看两个日志

```bash
tail -30 ~/.vnc/*.log            # Xvnc 与会话日志
cat /tmp/k1-vnc-app.log          # 程序的输出（用脚本启动时）
```

### 10.5 更轻的备选：网页屏（连 VNC 都不用装）

```bash
python3 main.py --real --ui-mode web --no-browser
```
手机/笔记本浏览器打开 `http://板子IP:8088/screen`，同一套界面、同样可点击，零安装。

### 10.6 板子完全没网怎么办

VNC 服务端要在板子上装，所以必须有网络（WiFi 或网线）。
真的一点网都没有时：在有网的电脑上下载 riscv64 的 `.deb`
（`apt download tigervnc-standalone-server` 或从镜像站取 `tigervnc-standalone-server_*_riscv64.deb`
以及依赖 `tigervnc-common`、`libvncserver1`、`xserver-common`），拷到 U 盘后 `dpkg -i *.deb`。
